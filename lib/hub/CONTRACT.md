# Custom hiring contract (shared implementation agreement)
Root integrates public API/runtime, migrations, deployment. Backend owns lib/hub (except this file), app/api/hub/[...path]/route.ts, tests/hub/*.test.ts. Workspace owns lib/google and tests/google/*.test.ts. Frontend owns components/hub, app/team/page.tsx, app/assessment/[token]/page.tsx, app/interview/[token]/page.tsx, components/careers/experience.tsx, its own CSS.

Use existing public Job/ApplicationField types in lib/hiring/types. Keep native anchors. Database is D1, files private R2 BUCKET. No Ashby/Resend/Trigger runtime. Existing SQL migration is applied: append schema via lib/hub/schema.ts and root reexports/generates.

Staff APIs /api/hub/* JSON {data: ...} success, {error:{message,code}} failure. Every staff endpoint calls requireHubMember(request) exported from lib/hub/auth.ts (root writes this). Auth returns {email,userId,role:'admin'|'recruiter'}. Sites trusted identity headers + server ADMIN_EMAILS owner bootstrap + explicit hub_members. Config is env from cloudflare:workers/process.env. Origin validation on all writes, bounded JSON. Member records may store normalized email. Dashboard never returns secret values.

POST /api/hub/process => root background dispatcher using hub task leases and google adapters.

HubJob extends Job {status,fields,formVersion:number,rules:Rule[],autoReject:boolean,rejectionTemplate:string,assessmentPrompt?:string}. Rule {fieldPath,operator:'equals'|'not_equals'|'contains'|'gte'|'lte'|'in'|'not_in',value:string|number|boolean|string[],reason:string,enabled:boolean} deterministic only, activation approved explicitly. Summary {id,name,email,jobId,jobTitle,stage,qualification:'pass'|'review'|'fail',assignee:string|null,createdAt,updatedAt,source:string,driveFolderUrl?:string}. Detail extends summary {answers:FieldSubmission[],fields:ApplicationField[],files:[{id,filename,contentType,size,url}],history:[{id,type,text,actor,createdAt}],notes:[...],communications:[{id,subject,body,status,createdAt}],assessment?:{id,status,prompt,answer?,submittedAt?},interview?:{id,status,start?,end?,timeZone?,meetUrl?,bookingUrl?},scorecards:[{id,actor,score,criteria,text,createdAt}],qualificationEvidence:[{fieldPath,reason,matched:boolean,value:unknown}]}. Store integer ms dates.

HubStore constructor(db:D1Database). Required public adapter methods:
listPublishedJobs():Promise<Job[]>; jobDefinition(id):Promise<JobDefinition>; acceptApplication(input:ApplicationInput):Promise<{id:string}> (application + answers snapshot + files match + archive task in ATOMIC D1 batch; id deterministically derived from submissionKey, avoid duplicates; no external calls).
Private uploads recorded hub_files: id raw handle? secret hashed token; objectKey private; linked only at accept. Root owns upload HTTP writing DB rows in hub_files, schema must have: id text PK (=handle hash), job_id, field_path, filename, content_type, size integer, object_key unique, uploaded_at integer nullable, application_id nullable, expires_at integer, session_hash text.
File field answers use raw privateToken handle; lookup id SHA256(handle), require uploaded_at and session checks before accept. Job form snapshot persists original fields at apply.
Task schema hub_tasks: id text PK, application_id, kind:'gmail'|'drive'|'calendar', payload_json, status:'pending'|'running'|'done'|'failed'|'uncertain', attempts integer, run_after integer, lease_until integer nullable, lease_token nullable, last_error nullable, result_json nullable, created_at,updated_at. Lease compare+swap (not SELECT then blind UPDATE). Gmail action payload {to,subject,body,messageId}; drive payload {applicationId}; calendar payload {interviewId,...}. Unique decision key via task id prevents repeated rejection mail. Application detail export from local records for Drive.
HubStore tasks():Promise<Task[]>; claimTask(now):Promise<Task|null> including leaseToken; finishTask(id,leaseToken,{status,result?,error?,runAfter?}):Promise<void>; getApplication(id):Promise<ApplicationDetail>.

Google module exports class GoogleWorkspace {constructor(config:{clientId,clientSecret,refreshToken,sender,calendarId?,driveRootId?},fetcher?:typeof fetch); sendMail({to,subject,body,messageId}):Promise<{id,threadId}>; reconcileMail(messageId):Promise<...|null>; busy({start,end,calendarIds?}):Promise<{start,end}[]>; createInterview({id,title,email,start,end,timeZone}):Promise<{id,meetUrl,start,end}>; cancelInterview(id):Promise<void>; updateInterview(same input):Promise<...>; archiveApplication(detail,files [{name,bytes:Uint8Array,mimeType}],existingFolderId?):Promise<{folderId,folderUrl}>}. Gmail ambiguous calls throw error with uncertain=true (no blind retry). Calendar deterministic event IDs + detect conflicts. Drive idempotent metadata/property identity. Google helper oauth authorizationUrl, exchangeCode, seal/openToken AES-GCM key secret root passes. Module provides config status but no app routes/schema changes.

Public secure links: hub_links table token_hash PK,application_id,kind assessment/interview,expires_at,used_at nullable, payload_json. Raw tokens appear only emailed URLs. Root/Backend collaborate public /api/candidate/:token endpoints GET detail limited to own assessment/interview jobTitle; POST assessment {answer}, booking {start,timeZone}, reschedule/cancel. Tokens expire/revoke, no other PII. Invitations enqueue mail plus hash-only stored links. Interview slots generated from Google freebusy + local reservations. No unauthenticated application-by-id access.

Country of residence preset uses `country_of_residence`, a required ValueSelect with the complete ISO country/territory catalog. Country membership rules use `in` or `not_in` with a nonempty array of saved ISO codes; the applicant always receives the full catalog. Country eligibility is deterministic and excluded from AI match evidence. Existing automatic-rejection settings control whether a failed rule queues a rejection. Private recovery drafts may retain an incomplete selection; published job validation must reject it.

Applicant review browsing: authenticated list/detail responses may include `viewedAt` for the signed-in staff member only. `POST /api/hub/applications/:id/viewed` records the first view idempotently without changing application stage, revision, history, or email tasks. `GET /api/hub/applications/:id/navigation` accepts the list's filters and returns `{previousId,nextId,position,total}` across pages in the same ordering (up to 10,000 matches). `GET`/`HEAD /api/files/:id?preview=1` privately render verified PDF/PNG/JPEG/WebP originals with byte-range support; Word DOC/DOCX originals return a bounded plain-text preview from a local isolated parser, with X-Preview-Format: word-text and X-Preview-Truncated metadata; original downloads remain unchanged. Preview requests never change AI scores or hiring decisions.
